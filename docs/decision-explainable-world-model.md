# 候補の比較と収束

## 1. 評価軸

最初の一機能を選ぶため、次の軸を用いる。5点が望ましい。

- 本質性: 人狼固有の難しさを捉えるか
- 基盤性: 後続機能が再利用できるか
- 実装可能性: 現在の小さなサンプルコードから着手できるか
- 評価可能性: 単体テストと対戦実験で良否を測れるか
- 説明可能性: 判断理由を人に示せるか
- 研究性: 発表で明確な問いを立てられるか
- データ非依存: 大規模な学習データなしでもMVPを作れるか

## 3. 採用理由

### 3.1 発言を信じ過ぎないことを構造で保証できる

発言をイベントとして記録し、世界ごとに「その役職の人物がその発言をする尤度」を掛ける。ハードなゲーム事実と、疑わしい発言証拠を分離できる。

### 3.2 嘘の一貫性の土台になる

嘘管理器は非常に魅力的な次候補である。しかし「どの嘘がどの世界で成立するか」を判定するには先に可能世界表現が必要である。よって順序として推定器が先になる。

### 3.3 2020年の失敗から学べる

深層学習による役職推定精度の改善が勝率改善につながらなかった結果は、分類精度と方策の間に設計層が必要であることを示唆する。今回の機能では、推定結果を説明付きの評価値として投票へ接続し、推定単体と勝率を別々に測る。

### 3.4 小規模な正解系を作れる

5人人狼では、自分以外の役職割当てを全列挙できる。近似推論を急いで導入せず、制約・確率・説明が正しいことを確認できる。15人版へ拡張するとき、この全列挙版をテストオラクルとして使える。

### 3.5 既存コードの弱点へ直接効く

現在のサンプルは候補から `random.choice` し、狂人・人狼の偽判定も乱数で決める。時系列の発言は保存するが、発言者の役職仮説、役職数制約、発言の信用度、世界全体の整合性、説明を持たない。可能世界推定器を入れると、まず投票候補を決定的に選ぶ改善ができ、後に偽判定の一貫性管理へ同じ基盤を使える。

### 3.6 確率を、対話で使える理由へ変換できる

人狼における推定は、自己完結した認識問題ではない。たとえ自分だけが正しい人狼候補を高確率で推定しても、多数派の投票を動かせなければ処刑には至らない。「人狼確率が最も高い」という説明はエージェント内部の選択規則にすぎず、他者が共有できる理由ではない。

可能世界モデルを採用する意義は、数値を出せることよりも、数値の手前にある論証を保持できることにある。どの公開観測があり、どの制約が働き、どの世界が消え、どの代替仮説が残り、それでもなぜ一つの仮説を優先したかを、相手が検討できる形で提示できる。この論証構造は、後続の説得機能が発言を生成する際の材料になる。

## 4. 今回は選ばない理由

### 一貫した嘘管理器

第二候補。狭く明快で、現在の `SamplePossessed.get_fake_judge()` と `SampleWerewolf.get_fake_judge()` の乱数ロジックを直接置換できる。一方で、世界モデルを内部に作らずに実装すると、局所整合だけのif文群になり、将来の相手視点や説明へ再利用しにくい。可能世界推定器の次に実装する。

### 相手から見た自己信用推定器

ユーザーの問題意識に非常に近い。ただし正解ラベルが直接観測できず、各相手の私有情報と推論方式も不明である。最初は公開信念モデルを基準線として作り、対戦ログから相手別の差分を学ぶ順序が堅い。

### 説得効果予測器

多数決ゲームの核心であり、長期的には重要である。ただし「発言によって誰の信念がどう変わったか」は通常のAIWolfログから直接は見えず、投票だけでは多義的である。状態推定と因果評価の基盤が先に必要。

### 深層学習役職分類器

実装例と評価指標は明快だが、独立分類では役職数制約を破り、説明性も弱い。また、精度改善が勝率改善を保証しないことが既存研究から分かる。将来は世界のソフト尤度を出す部品として利用する。

### 強化学習

勝敗報酬は疎で、発話と行動の寄与分解が難しい。現在の段階で導入すると、制約違反や説明不能な方策を招きやすい。明示的な状態、行動候補、評価ログが整った後に比較対象として入れる。

### キャラクター性

魅力的だが、文体だけの表層的個性と、リスク選好や説得スタイルとしての戦略的人格を分ける必要がある。まず同じ状態に同じ判断を返す基準エージェントを作らないと効果測定が難しい。

## 5. 研究問い

主問い:

> ルール制約を満たす可能世界分布と、その更新根拠を明示する役職推定は、独立なヒューリスティック推定に比べ、推定の整合性、較正、説明可能性、および決定的投票方策の性能を改善できるか。

副問い:

1. 発言を事実ではなく尤度証拠として扱うことで、騙りに対する頑健性は上がるか。
2. 発言時点を特徴に入れることで、同じ発言内容でも推定更新が改善するか。
3. ハード制約、手動尤度、学習尤度の各段階で何が改善するか。
4. 推定精度の改善と勝率の改善は、どの条件で一致または乖離するか。
5. 世界除外理由、仮説比較、推論のつながりを示す説明は、人間が判断を検査し、反論するのに十分か。
6. 確率だけを提示する場合に比べ、公開根拠から構成した説明は他エージェントまたは人間の投票を動かせるか。

## 6. 決定境界

次の条件が成立すれば、この機能選択を確定する。

- 5人人狼を最初の対象としてよい
- 「まず推定と説明、次に説得と嘘生成」という順序に合意できる
- MVPの尤度は手動でもよく、深層学習は第二段階でよい

反対に、最短で見栄えのするデモを優先するなら「一貫した偽占い管理器」、人間対象の研究を最優先するなら「相手から見た自己信用推定器」へ切り替える余地がある。
