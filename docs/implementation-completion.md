# 説明可能な人狼AIの実装詳細

## 対象と実装の位置付け

`docs/` の7文書を読み、機能候補90項目の一覧を、全部同時に実装する要求仕様とは解釈せず、
`requirements-explainable-role-estimator.md` に選定された5人版推定器を今回の対象にした。
既存の第三段階までの推論核・占い師接続・尤度設定を引き継ぎ、公開視点、反実仮想、
構造化反論、推論グラフ、評価器を追加した。新規性や実戦性能を証明したものではない。

## 推論の手順

### 1. 成立する役職世界を列挙する

全プレイヤーを固定順のタプルにし、その順序に対応する役職タプルを`World`とする。
村人の自己視点では残り4人に4種類を割り当てるので24世界、占い師の自己視点では
村人が2人いるので12世界、誰の役職も知らない公開視点では60世界となる。
この小さい正解系を明示的に保持する。15人入力は計算を始める前に拒否する。

有効な全世界に一様事前分布を置く。各世界には最初から役職人数の制約が入っているため、
各人を独立分類して最後に人数調整する処理は不要になる。

### 2. 確定観測と発言の尤度を分ける

世界`w`、観測`o_t`、それ以前の履歴`h_t`に対して、更新は次の式になる。

```text
log_weight_t(w) = log_weight_(t-1)(w) + log P(o_t | w, h_t)
P_t(w) = exp(log_weight_t(w) - logsumexp(log_weight_t))
P(agent = role) = sum(P_t(w) for worlds assigning role to agent)
```

自己占いに反する世界、確認された襲撃死の対象が人狼である世界は重みを0にする。
他者の占い報告、CO、投票の尤度は0より大きい値だけを許す。
真占い師の戦略的虚偽や、狂人の偶然正しい報告を排除しない。

遅いCO、対抗CO後の発言、同じ対象への矛盾報告、宣言から変更された投票は
過去イベントと時点を参照する。パラメータは`LikelihoodParameters`に意味名でまとめ、
範囲とバージョンを検査する。今回の追加係数を含む既定版は`transparent-v2`。
値は検証用の仮説であり、較正された経験的確率ではない。

### 3. 履歴と監査データを残す

`Observation`はID、日、ターン、発話順、フェーズ、取得源、公開範囲を持つ。
同じID・同じ内容の再取込みは無操作。同じIDで内容が変われば例外となる。
不正な尤度や全世界消滅時には既存分布と履歴を更新しない。

各`BeliefUpdate.world_evidence`は、`estimator.worlds`と同じ順序の尤度・規則名・版番号を保持する。
`snapshot(step)`は観測直後の分布を保存済み状態から返す。
`timeline(agent)`は変化の起点となったイベントIDを伴う。
これによって過去の判断に将来の情報が混ざることを避ける。

### 4. 行動を決定する

`choose_vote()`は生存する自己以外の全候補で人狼確率を比較する。
同点時にはゲーム開始時の入力順を優先し、`VoteDecision.scores`に候補別得点を残す。
5人版の村人・占い師では、従来の黒報告などによる候補絞込みを推定器の前に置かない。
発言で作った候補を確定扱いすると、発言をソフト証拠にする設計と衝突するためである。
実際の`vote()`要求でも再計算するので、直前にVOTE発言がなくても自分へ投票しない。

狂人・人狼の目的関数へこの村側投票を流用しない。
占い対象やCO時機、狼陣営の既存サンプル方策は今回の投票MVPの対象外とする。

## 公開説明を別に再計算する理由

当初のコードは私有証拠の文章を削除していたが、自己視点の確率を公開説明に表示していた。
さらに、私有結果で変わった分布に公開発言を適用すると、公開イベントの寄与量にも私有結果が現れる。
これは単なる文字列フィルターでは防げない。

そこで`public_view()`は自己役職にも条件付けず、60世界から公開イベントだけを再生する。
公開説明の確率、代替仮説の順序、根拠の寄与、グラフをすべてこの公開分布から作る。
自己視点の投票対象に公開根拠が乏しければ、その不足を明記する。
公開モデルで別候補が優勢なら、その事実も留保として表示する。

この保証は「同じ対象についての公開説明」に対するものである。
私有情報を使って選んだ行動そのものから他者が情報を推測することまで防ぐものではない。
推論核が作る説明は構造化データと固定テンプレートであり、自由文の説得生成ではない。

## 反論と推論グラフ

`reasoning_graph()`は観測ノードと規則ノードから、人狼仮説への`supports`または`weakens`の辺を作る。
これは実際の更新前後の周辺確率差に対応する最小グラフで、完全な論理証明や因果グラフではない。
世界別尤度は監査データから追える。説明に採用した証拠IDも同じ観測ノードに対応する。

```python
from belief_evaluation import replay_record
from belief_explanations import Objection, ObjectionKind, respond_to_objection

estimator = replay_record(record)
answer = respond_to_objection(
    estimator,
    "Agent[03]",
    Objection(ObjectionKind.OBSERVATION, observation_id="talk:1:0"),
)
```

観測の争いには、その証拠を除いた再生結果を返す。後続イベントの時点文脈も再計算する。
規則の争いには、適用規則と尤度モデルの版を示す。代替仮説には、公開制約の下で世界が残るかを返す。
異議だけで観測を削除したり、真実へ書き換えたりしない。
新しい観測は別IDで`observe()`へ入力する。私有イベントを指定した公開の反論要求は拒否する。
証拠除外は感度分析であって、その発言を現実に変えた場合の因果効果ではない。

## 実装中の試行と問題修正

| 問題 | 判断と修正 | 確認方法 |
|---|---|---|
| 公開説明の数値が私有結果に依存 | 公開分布を独立再計算 | 異なる私有占いでも公開Argumentとグラフが一致 |
| 自分の投票宣言から確信が増幅 | 自己行動を尤度1の観測とする | 宣言前後で自己分布が不変 |
| ソフト尤度0が確定制約として動作 | ゼロはハード制約専用 | 不正モデルを拒否し履歴が不変 |
| 同じIDの内容変更を黙って無視 | 完全一致だけ冪等にする | ID衝突の例外と状態不変 |
| 襲撃対象と死亡を混同 | 公開死亡リストとの一致を確認 | 生存した襲撃対象を非人狼確定にしない |
| 他人への役職主張を自己CO扱い | 発言者とCO対象の一致を確認 | 第三者COを変換しない |
| 発言していないと自分へ投票 | vote境界で候補を再計算 | talkなしでも合法な別候補を選択 |
| SDK境界と計算が密結合しがち | 推論・説明・評価を別モジュールへ | 核はSDK不要、接続は実SDKで検査 |

## 検証とデモ

```console
python -m unittest discover -s tests -v
python belief_evaluation.py examples/five_player.json --output output/evaluation.json
```

検証環境のAIWolf SDK入りPythonで40テスト成功。
100回再生の投票・説明一致、人数制約、私有情報境界、例外時の状態保存を含む。
SDKがない環境では接続テストをスキップするため、全件成功の確認にはSDKを用いる。

合成局面1件で、自己以外4人を評価した動作例:

| 条件 | Brier score | log loss | 投票対象 |
|---|---:|---:|---|
| ハード制約のみ | 0.750 | 1.386 | Agent[02] |
| ソフト証拠あり | 0.377 | 0.694 | Agent[03] |

Brierは全4役職の二乗誤差和の対象者平均（0〜2）。log lossは自然対数、確率下限は`1e-15`。
ECEは予測上位役職の信頼度を10区間に分けた誤差で、各区間件数も出す。
正解役職表は推論完了後に採点器だけが読み取る。上位5世界への正解包含、役職人数誤差、
投票的中、ランダム投票の的中期待値も出す。最後の一時点の評価であり、試合結果ではない。

## 未検証事項と次段階

実対戦サーバとの試合、尤度の学習、実戦勝率、説明の説得効果は未検証。
手動尤度には行動間の相関やプレイヤー固有傾向の単純化が残る。
公開信念は特定の相手の私有情報や推論方式を知るモデルではなく、共通の基準視点である。
独立分類器・現サンプル・実対戦ログとの総合比較はまだない。

次段階では試合単位で学習・評価データを分け、役職別勝率と較正を測る。
一貫した嘘生成や説得生成は、この世界・証拠・説明の基盤を使って別機能として構築する。
